# Impact-Ranked Next Steps

This roadmap is intentionally ordered by expected information gain, not by implementation convenience.

## 1. Establish at least three executed whole-system baselines before deeper integration

Do not spend substantial effort adapting Ensemble while it is the only executed complete system. That would create anchoring pressure around Ensemble's ontology and make later systems look awkward merely because they differ.

The immediate execution targets are:

1. PsychSim, because it provides the strongest explicit Theory of Mind and belief-model comparison in the current queue.
2. FAtiMA Toolkit, because it provides a mature affective and social character architecture closer to the whole-person target.
3. Ensemble, already executed, should remain frozen at the original-domain level until the other two have reached the same qualification state.

The first decision gate is reached when Ensemble, PsychSim, and FAtiMA have all demonstrated meaningful native state transitions with preserved traces and no behavioral rewriting.

## 2. Use a small discriminating battery before the full 20-scenario battery

The complete battery remains authoritative, but the first comparative pass should use scenarios that most strongly separate architectural families.

Priority scenarios:

- B01 History Divergence, because longitudinal history dependence is central to perceived individuality.
- B02 Social Differentiation, because partner-specific behavior is a foundational test of relationship continuity.
- B03 Unfinished Concern, because persistent latent concerns separate continuously motivated systems from reactive state machines.
- B09 False Belief and Limited Knowledge, because it directly tests epistemic boundaries and Theory of Mind.

These four scenarios form the Core Discriminating Battery. They are not a replacement for the full battery. They are an early information-gain filter.

## 3. Build only thin adapters for the Core Discriminating Battery

Adapters should be implemented only after the original baseline has executed. Each adapter should support the smallest mapping necessary to expose candidate behavior in B01, B02, B03, and B09.

A candidate may mark a scenario NOT EXPRESSIBLE. That result is useful evidence and must not be repaired by adding cognition to the adapter.

Do not normalize away architectural differences. Preserve native actions, native state, native timing, and native model outputs alongside common trace records.

## 4. Create a baseline evidence matrix before naming Champion 0

Do not select Champion 0 from an aggregate score alone. For each executed and adapted baseline, maintain a dimension-level evidence matrix covering at minimum:

- history sensitivity
- social differentiation
- unfinished concern persistence
- epistemic limitation
- Theory of Mind
- emotional inertia
- motive competition
- adaptation from consequence
- spontaneous activity
- computational cost
- authoring burden
- licensing constraints

Each cell should be tagged as OBSERVED STRENGTH, OBSERVED WEAKNESS, NOT EXPRESSIBLE, NOT TESTED, or MIXED.

Champion 0 should be the strongest practical whole-system starting point, not necessarily the system with the largest number of sophisticated mechanisms.

## 5. Add causal probes immediately after any apparent strength

When a baseline performs unusually well, trace that result back to the smallest candidate mechanism before integration.

For example, if PsychSim handles B09 well, determine whether the result depends on explicit nested mental models, belief update, decision horizon, or another mechanism. If Ensemble handles B01 well, determine which social-history and volition paths actually preserve the behavioral divergence.

Do not award mechanism credit from architecture diagrams or module names.

## 6. Measure old-school performance during baseline testing, not after synthesis

Record decision latency, memory usage, state growth, and scaling as soon as each system is adapted.

Use at least 1, 10, 50, and 100 agents where the system can support equivalent ongoing cognition. Attempt 500 agents when technically meaningful.

This prevents the project from discovering too late that a behaviorally attractive mechanism violates the lightweight target.

## 7. Run mechanism tournaments only after baseline evidence identifies a confirmed weakness

Do not begin with broad component mixing.

A mechanism tournament starts only when a baseline comparison demonstrates a real behavioral deficit. Then compare donor mechanisms that address that specific deficit.

Examples include FAtiMA appraisal versus GAMYGDALA appraisal, PsychSim mental models versus simpler opponent models, MicroPsi motivation versus BDI goal persistence, and Creatures-style drive or reinforcement dynamics versus explicit utility updates.

The winner must improve behavior enough to justify its computational and integration cost.

## 8. Continue software archaeology as a targeted search process

Archaeology should answer specific unresolved behavioral problems rather than expand the catalog indefinitely.

High-value current archaeology remains Oz, Hap, Em, ABL, Façade descendants, Creatures mechanisms, and other complete pre-LLM believable-agent systems with obtainable code.

New candidates should move ahead of the existing queue only when there is evidence that they are more complete, more behaviorally relevant, more reproducible, or substantially more efficient.

## Near-term decision gates

### Gate A

Ensemble, PsychSim, and FAtiMA have each executed a native meaningful state transition without behavioral rewriting.

### Gate B

All three have thin adapters or explicit NOT EXPRESSIBLE determinations for the Core Discriminating Battery.

### Gate C

A baseline evidence matrix exists with preserved traces and initial performance measurements.

### Gate D

Champion 0 is selected from evidence, or the project explicitly records that no current complete baseline is strong enough to deserve Champion status.

### Gate E

The first mechanism tournament is selected from a confirmed Champion 0 weakness rather than from architectural preference.

## Current execution order

1. Execute PsychSim's native Theory of Mind behavior and preserve a trace.
2. Execute a FAtiMA native appraisal plus decision path and preserve a trace.
3. Implement the Core Discriminating Battery schema and evidence matrix.
4. Adapt Ensemble, PsychSim, and FAtiMA only far enough to run the core battery.
5. Compare whole-system results and profile performance.
6. Select Champion 0 or explicitly decline to select one.
7. Identify the highest-impact confirmed weakness.
8. Search the mechanism catalog and broader prior art for donors addressing that weakness.
9. Run the first mechanism tournament.
10. Only then construct the first hybrid challenger.
